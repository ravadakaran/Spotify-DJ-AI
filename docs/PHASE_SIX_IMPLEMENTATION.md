## Performance protocol

`npm run benchmark` starts its own real MongoDB replica set and one application process. Default: two rooms, ten unique clients each, 60-second warmup, 600-second measurement, two votes and one chat per second per room. `BENCH_USERS` accepts 5–50; `BENCH_SECONDS` and `BENCH_WARMUP` control duration. Run independently of other test processes for isolated measurements. The corrected long desktop run included dependency restoration, clean-directory install/tests and browser verification during measurement; it is a local development workload, not a dedicated benchmark machine.

Every snapshot listener records the monotonic application time and queue hash for its room/revision. A mutation waits for every client to apply its identical revision; missing revisions, disconnects, rejected commands and divergence count as failures. Queue time starts at entry to the server room command processor (after socket token verification); general fan-out starts before the client emits and includes authentication. These scripted clients do not measure React rendering. Existing browser timings supply a separate two-context DOM check. Inter-client skew is reported independently. REST catalog timing includes HTTP/auth/validation/database/JSON processing. No AI calls are disguised as template benchmarks.

The initial long run probed REST at two requests/second from one IP, exactly the configured 120/minute budget, and recorded twelve boundary-window 429 responses. It is preserved as `phase-six-load-10-initial.json`; the corrected probe uses 0.5 requests/second/room while retaining two votes and one chat/second/room. Reports identify the pre-change base commit; implementation is uncommitted, with final source hashes recorded separately. The original long-run transport throttle override was 500/minute; subsequent stress/corrected runs use the deployed 120/minute default.

Reports include raw traces, P50/P95/P99/max, CPU/RAM/runtime, commit, samples of process memory, event-loop delay and buffer depth. Receipt maps retain 256 revisions/client and 512 server timestamps; server room/event/queue limits are unchanged. Trace reports intentionally grow with the declared finite run duration. Memory samples cover the application/harness Node process, not the MongoDB child. Same-process clients compete with the application and are a reproducible local stress test, not remote-device capacity proof. A short 50-client run cannot certify a ten-minute 50-client workload.

## Security and accessibility

Body-parser and Multer were upgraded within the Express/Node stack after official advisory review. Production/full audit reports are stored separately. The full audit still identifies a low-severity deepmerge/Jest development dependency; no patched deepmerge release was available from the registry during this run, and a forced downgrade to Jest 25 was not accepted. Consult the saved reports for exact counts; package registry summaries were inconsistent during installation.

`npm run security:scan` checks tracked/nonignored source and all reachable Git history additions for private-key, JWT, provider-key and MongoDB credential signatures. It prints counts and locations only. It is a signature scan, not proof that every possible secret is absent.

Phase-six integration checks reject object-valued login credentials, prototype fields, oversized JSON, malformed media IDs and unauthorized session end over HTTP/socket. Cookie refresh rejects missing CSRF header and nonexact origins; ordinary APIs authenticate explicit bearer tokens and do not grant credentialed cross-origin access. Existing suites cover media containment, upload validation, socket origin/auth, forged roles, malicious model output, persistence retry and crash/replay. New checks exercise slow-transport disconnection, room isolation and writer readiness degradation.

The browser journey audits computed solid-color contrast and named/focusable controls on welcome, overview/catalog, lounge/social/AI, analytics and mobile dashboard/admin views. Secondary text colors now pass those checks. Keyboard Tab from email to password, visible focus styling and reduced-motion button feedback are included. Stored script markup is rendered as text in chat. This is targeted review, not a full WCAG or screen-reader certification; gradients, opacity groups, icon contrast and all assistive technologies remain outside the automated audit.

## Private deployment and recovery

`deploy/Caddyfile` terminates HTTPS and proxies HTTP/WebSocket to loopback port 3000. `deploy/ai-dj.service` runs exactly one Node process with restricted writes. `TRUST_LOOPBACK_PROXY=true` trusts forwarded HTTP addresses only from loopback; keep port 3000 unreachable externally. Socket handshake throttling still groups by transport peer (the local proxy), with a bounded 120/minute allowance supporting a two-room 100-client connection burst; excessive reconnects share this limit. Socket per-connection and room chat throttles still apply. Actual Caddy/systemd/TLS deployment is unexecuted on this Windows host. See the operating runbook before installing.

`npm run backup -- backup DIRECTORY` and `npm run backup -- restore DIRECTORY` require `BACKUP_WRITERS_STOPPED=true`. Stop the app and all other writers first. The offline logical snapshot streams BSON-preserving Extended JSON documents, collection options/validators/indexes, migration ledger and referenced assets with SHA-256 manifest. It does not use installed MongoDB Database Tools; none were present. It excludes system collections and does not export database users/roles. Database credentials and JWT configuration must be retained privately outside the backup. Hashes detect accidental corruption, not malicious replacement of both manifest and contents; use trusted storage and restrictive OS ACLs.

Restore verifies every checksum before database writes, refuses an existing destination directory for backup and any nonempty database/asset destination for restore. Asset realpaths must stay inside the selected source. Unsupported collection types fail closed. Restored TTL dates retain their original expiry. A failed partial restore must be discarded by the operator and retried into another verified empty target; the tool never drops databases. Only the application's ordinary collections/index options are supported, not a general MongoDB migration product.

The automated rehearsal closes room authority and flushes, backs up a disposable database plus an original test-byte asset, restores into a separate clean database/directory, checks every collection count, asset bytes, strict validator, migrations and replay. Restored room epoch changes, presence clears and playback remains paused. This exercises logical recovery, not mongodump/mongorestore, VM-volume recovery or restoration of the private library. No schema migration or socket event name changes are introduced by Phase 6.

## Measured stress evidence

Two rooms with 50 clients each passed 10-second warmup plus 60-second measurement. Queue processor-entry to last application: P95 45.06 ms, max 83.78 ms; client emit to last application (all mutation types) max 153.65 ms; REST P95 50.91 ms. Zero rejected commands, disconnects or divergent snapshots. Sampled Node peak RSS was 257.6 MiB; largest sampled event buffer 38/500; overall event-loop P99 35.88 ms. This does not measure browser rendering, adverse network conditions or indefinite memory growth. The initial ten-minute run met latency thresholds but failed twelve REST probes due to rate limiting; those failures are retained, not filtered out. The corrected long run had zero command failures and no divergence across 2,400 queue and 1,200 chat events plus 600 successful REST probes. Its queue P95 was 24.28 ms, but max 225.00 ms missed the strict 100 ms maximum; fan-out max 309.80 ms and REST P95 24.27 ms met their thresholds. Event-loop max was 219.68 ms. Concurrent desktop verification prevents treating this as isolated-load acceptance. Do not claim queue latency certified; an isolated rerun/investigation remains open. The harness now returns nonzero for a failed measured threshold as well as command failures; the recorded long run preceded that exit-code correction, so its recorded acceptance.queue=false is authoritative. Subsequent traces also include elapsed monotonic time for correlating outliers with resource samples.

## Demo and retrospective

The two-context Playwright journey records the Host viewport while a second independent session joins, votes, chats, reacts, runs a timed battle, approves a compatible segue, asks cited Q&A, reconnects, likes a track, ends and views analytics/dashboard/admin fitting. The video uses generated silence and metadata fixtures, not demonstration music or a real model. Evidence filenames use phase-six prefixes to preserve historical runs.

The prototype now covers all three functional epics. Deterministic hard eligibility, serialized room authority and bounded transactional batches survived incremental expansion without introducing services or a second database pool. Real-data evaluation is the remaining product-quality constraint: synthetic fixtures validate algorithms and contracts but cannot certify real-world recommendation, sentiment, musical or LLM quality. Deployment templates and disposable recovery evidence reduce operational uncertainty without claiming a live deployment. Long-session summary aggregation and dashboard/training capacity remain bounded limitations documented in Phase 5.

Final harness verification: two rooms × 5 clients, 2-second warmup plus 10-second measurement passed with zero failures after adding threshold-aware process exit status, nonempty-sample guards and elapsed-time trace fields. This smoke does not replace the long-run maximum-latency gate.
